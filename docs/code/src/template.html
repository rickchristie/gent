WITH DURABLE HISTORY

Context edits are explicit.

ExecutionContext owns entries and selections. Append, reorder, expiry, removal, and replacement become structured changes. A pin change creates a replacement record; it does not edit old evidence.

Records, iterations, and compaction proposals

HistoryEntry replaces the old content type named Iteration. The executor’s iteration counter retains its meaning. A final answer can enter history without entering the next scratchpad.

CompactionTrigger decides when to compact. CompactionStrategy proposes appended entries and a complete selection. The executor accepts the marker, selection, trigger baseline, accounting, and checkpoint together. Sliding windows preserve selected originals; summarization creates new summary entries.

A failed compaction preserves the old selection and records the error. No text Diff is kept. HistoryChange describes the actual transition.

YOUR STORAGE ADAPTER

Recorder

type Recorder interface {
    Save(context.Context, *SaveBatch) error
}

Check the lease and expected cursor, handle identical batches idempotently, store the batch atomically, then return success. A nil recorder gives in-memory acceptance. Shared storage supplies crash durability.

What happens when saving or publication fails?

PersistenceError retains the exact failed or uncertain batch. New acceptance stops. The application reconciles that exact batch with storage. After reconciliation, load the accepted store bundle into fresh execution bindings. Retry does not revive an already stopped ExecutionContext.

ApplyBatch is a pure, idempotent reducer for materializing a view. It provides validation, while your storage provides transactions and fencing. A failed broadcast after commit is a delivery problem; a full read still finds the data.

What can this release resume?

Root ReAct execution supports initial, iteration-ready, decision-ready, tool-ready, tool-completed, iteration-completed, compaction-completed, and terminal checkpoints. A saved successful model response can be reused before a decision checkpoint exists.

Active child frames cannot resume. Interrupted JavaScript returns saved partial results and recovery guidance without restoring a VM stack or restarting the script. Completed children remain archived. Unknown schemas, codecs, incompatible configuration, and unsupported custom state are rejected explicitly.

Set WithRecoveryVersion for application behavior. Use CheckpointState for mutable custom fields. Worker cancellation means interruption; CancelRun expresses intentional terminal cancellation.

BEFORE AN EFFECT

Hooks can shape input.

Model, tool, and system-prompt before-hooks may modify effective input. The managed boundary freezes that final input before it is sent outside Gent.

AFTER ACCEPTANCE

Observers see evidence.

Structured state-change subscribers and trace observers see accepted data. A slow display subscriber cannot drop durable evidence. Storage backpressure remains real.

Exact limits, retries, and repetition

Most limits use value > MaxValue during stats updates. Exact iteration limits use value >= MaxValue after a completed iteration. Prefix limits match individual prefixed stats, such as calls to a particular tool.

Saved accounting includes known progress beyond the checkpoint and is imported without replaying stat updates. Working-state gauges such as scratchpad length follow the restored selection. New physical attempts incur new work; reused saved results incur none.

ReAct’s repetition handling detects repeated output and applies its configured response. Its continuation frame saves the state needed to avoid resetting that behavior at takeover.
